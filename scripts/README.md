# AI-assisted Development Pipeline for vendor-management

This repository includes a lightweight framework to reduce the manual loop between planning, implementation, review and merge when working with AI. Instead of rebuilding prompts and review instructions every time, the project keeps a persistent memory of the product state, a clear backlog of increments and a small set of shell scripts that orchestrate the cycle.

The goal is to make the PM role explicit, keep Codex execution bounded by documented rules and make review repeatable against the original objective and DoD. The developer still decides what to build and when to merge, but the repetitive framing and review work becomes much faster and more consistent.

This repository now supports two operating modes:
- step-by-step mode, where you call `gen_prompt.sh`, `review_pr.sh` and `merge_pr.sh` separately;
- orchestrated mode, where `run_increment.sh` drives the full cycle using Gemini as PM/reviewer and the local Codex CLI as the technical executor.

## Prerequisites

- Bash-compatible terminal on Linux, macOS or WSL
- GitHub CLI (`gh`): https://cli.github.com/
- Codex CLI available in `PATH`
- `curl`
- Docker + Docker Compose access
- `python3`
- Gemini API key: https://aistudio.google.com/app/apikey
- VS Code command line (`code`) is optional, but recommended if you want the scripts to open generated files automatically.
- If `codex` is not available in your shell `PATH`, configure `CODEX_BIN` in the root `.env` with the absolute path to the Codex binary.

## Configure the root `.env`

Use `.env.example` as the starting point and create a `.env` file in the repository root.

Example:

```env
GEMINI_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-2.5-flash
GEMINI_MAX_RETRIES=3
GEMINI_FALLBACK_RETRY_SECONDS=60
# Optional when `codex` is not in PATH
# CODEX_BIN=/absolute/path/to/codex
CODEX_MODEL=gpt-5.4
CODEX_SANDBOX=workspace-write
CODEX_DANGEROUS_BYPASS=false
AUTO_MAX_CYCLES=3
AUTO_CHECK_INTERVAL=10
AUTO_CHECK_DISCOVERY_ATTEMPTS=12
AUTO_MERGE_ON_APPROVAL=true
AUTO_BRANCH_PREFIX=feature
AUTO_RESUME_ON_RPD=true
AUTO_RESUME_POLL_MINUTES=10
AUTO_RESUME_AFTER_RESET_MINUTES=5
```

Suggested setup:

```bash
cp .env.example .env
```

Important:
- This root `.env` is for local orchestration scripts only.
- The application itself still uses `backend/.env`.
- Do not move backend secrets into the root `.env`.
- `GEMINI_MAX_RETRIES` and `GEMINI_FALLBACK_RETRY_SECONDS` control automatic retry for short-lived Gemini limits like RPM and TPM.
- `AUTO_RESUME_ON_RPD` enables automatic resume after daily Gemini quota reset.
- `AUTO_RESUME_POLL_MINUTES` controls how often the cron job checks for due resumes.
- `AUTO_RESUME_AFTER_RESET_MINUTES` adds a small cushion after the daily reset before retrying automatically.

## Framework file structure

The AI-assisted workflow is composed of these files:

```text
docs/project_context.md
docs/pm_workflow.md
docs/codex_workflow.md
prompts/PROMPT_TEMPLATE.md
INCREMENTS.md
scripts/gen_prompt.sh
scripts/review_pr.sh
scripts/merge_pr.sh
scripts/check_setup.sh
scripts/run_increment.sh
scripts/resume_pending.sh
.github/workflows/test.yml

```

Runtime artifacts generated by the scripts:

```text
prompts/next_prompt.md
prompts/review_result.md
prompts/correction_prompt.md
prompts/generated/INC-XXX.md
```

## Ignored runtime artifacts

The repository should ignore the generated prompt artifacts:

```gitignore
prompts/next_prompt.md
prompts/review_result.md
prompts/correction_prompt.md
prompts/generated/
```

## How the pipeline works

1. Update `INCREMENTS.md` with the next desired increment.
2. Choose either step-by-step execution or one-command orchestration.
3. In step-by-step mode, run `gen_prompt.sh`, then let Codex implement the increment, then use `review_pr.sh` and `merge_pr.sh`.
4. In orchestrated mode, run `run_increment.sh`, which generates the prompt, executes Codex, opens or updates the PR, waits for checks, asks Gemini for review, sends correction prompts back to Codex when needed and merges on approval.
5. If Gemini daily quota is exhausted during orchestration, `run_increment.sh` writes a pending resume state and installs a user cron entry that polls until the next daily reset window is reached, then relaunches the increment automatically.

## Quick start for autonomous mode

1. Configure the root `.env`:

```bash
cp .env.example .env
```

2. Fill in `GEMINI_KEY`.
   If your project is provisioned for a different Gemini model, set `GEMINI_MODEL` explicitly in the root `.env`.
3. Validate local prerequisites:

```bash
./scripts/check_setup.sh
```

4. Run the next pending increment:

```bash
./scripts/run_increment.sh
```

5. Optional dry run before the first real execution:

```bash
./scripts/run_increment.sh --dry-run
```

## Script usage

### 0. Validate local automation prerequisites

Command:

```bash
./scripts/check_setup.sh
```

Optional deeper validation:

```bash
./scripts/check_setup.sh --deep
```

What it does:
- loads the root `.env` if present
- checks required commands and Git/GitHub authentication
- checks Docker access and backend local env presence
- confirms `GEMINI_KEY` is available
- in `--deep` mode, performs a minimal Gemini API round-trip and a minimal Codex batch round-trip

### 1. Generate the next Codex prompt

Command:

```bash
./scripts/gen_prompt.sh
```

Command for a specific pending increment:

```bash
./scripts/gen_prompt.sh --increment INC-001
```

What it does:
- loads the root `.env` if present
- validates `GEMINI_KEY`
- reads the first pending increment in `INCREMENTS.md`
- reads `docs/project_context.md`, `docs/pm_workflow.md` and `prompts/PROMPT_TEMPLATE.md`
- asks Gemini to act as PM and fill the template
- saves the result to `prompts/next_prompt.md`
- archives the same prompt to `prompts/generated/INC-XXX.md`
- opens the file in VS Code if `code` is available

Expected output:
- a ready-to-paste prompt for Codex in `prompts/next_prompt.md`
- a stable archived prompt tied to the increment code

### 2. Run the full increment automatically

Command:

```bash
./scripts/run_increment.sh
```

Command for a specific increment:

```bash
./scripts/run_increment.sh --increment INC-001
```

Useful flags:

```bash
./scripts/run_increment.sh --dry-run
./scripts/run_increment.sh --no-merge
./scripts/run_increment.sh --max-cycles 5
```

What it does:
- validates the local setup through `check_setup.sh`
- resolves the target increment from `INCREMENTS.md`
- generates the PM prompt with Gemini
- creates or resumes the target branch
- runs the local Codex CLI in non-interactive mode
- opens or updates the PR against `develop`
- waits for GitHub checks to appear and finish
- asks Gemini to review the PR against the archived prompt
- if Gemini rejects the PR, stores a correction prompt and sends it back to Codex
- if Gemini hits short-lived API limits, retries automatically based on `RetryInfo` or fallback wait values
- if Gemini hits daily request quota, stores a pending resume job and relies on a user cron poller to restart the increment after the reset window
- repeats until approval or until the maximum number of cycles is reached
- optionally merges automatically when the review is approved

Artifacts generated during the loop:
- `prompts/generated/INC-XXX.md`: the original PM prompt
- `prompts/generated/INC-XXX-executor-*.md`: executor prompts wrapped with automation context
- `prompts/generated/INC-XXX-*-events.jsonl`: raw Codex batch event log
- `prompts/generated/INC-XXX-*-last-message.md`: last Codex message captured from the run
- `prompts/generated/pending_rpd_resume.json`: pending resume state when daily Gemini quota is exhausted
- `prompts/generated/auto_resume.log`: cron-driven resume log
- `prompts/review_result.md`: latest Gemini review output
- `prompts/correction_prompt.md`: latest correction prompt when review fails

Important:
- the working tree must be clean before `run_increment.sh` starts;
- the PR must target `develop`;
- backlog-driven automation expects PR titles in the format `INC-XXX ...`.
- automatic daily resume depends on `crontab` being available for the current user.

### 3. Review the current PR with Gemini

Command for the PR attached to the current branch:

```bash
./scripts/review_pr.sh
```

Command for a specific PR number:

```bash
./scripts/review_pr.sh -PrNumber 123
```

Command for a non-backlog PR using an explicit prompt file:

```bash
./scripts/review_pr.sh -PrNumber 123 --prompt-file /absolute/path/to/prompt.md
```

What it does:
- loads the root `.env`
- validates `GEMINI_KEY` and `gh`
- resolves the PR metadata with `gh pr view`
- downloads the PR diff with `gh pr diff`
- reads `docs/project_context.md`, `docs/pm_workflow.md` and the archived prompt for the `INC-XXX` in the PR title
- asks Gemini to review the PR against the original objective, out of scope and DoD
- saves the result to `prompts/review_result.md`
- opens the result in VS Code if `code` is available
- returns exit code `0` for approved and `1` for rejected

Expected review output:
- first line must be `STATUS: APROVADO` or `STATUS: REPROVADO`
- item-by-item evaluation of the DoD
- correction prompt for Codex if the PR is rejected

### 4. Squash merge an approved PR and close the increment

Command for the PR attached to the current branch:

```bash
./scripts/merge_pr.sh
```

Command for a specific PR number:

```bash
./scripts/merge_pr.sh -PrNumber 123
./scripts/merge_pr.sh --yes -PrNumber 123
```

What it does:
- validates `gh`
- resolves the PR metadata and asks for confirmation
- runs `gh pr merge --squash --delete-branch`
- requires the PR base branch to be `develop`
- extracts `INC-XXX` from the PR title
- updates `INCREMENTS.md` on `develop` through the GitHub API after merge
- syncs the local `develop` branch when the working tree is clean

Important:
- The PR title must contain an `INC-XXX` code for deterministic review and automatic backlog completion.
- If the title does not contain an increment code, the script will fail instead of guessing.
- `review_pr.sh` can still review an out-of-band PR when you pass `--prompt-file`, but `merge_pr.sh` remains reserved for backlog-driven PRs targeting `develop`.

## Suggested working routine

### Preferred autonomous routine

1. Keep `develop` updated locally.
2. Ensure the root `.env` is configured from `.env.example`.
3. Validate the environment:

```bash
./scripts/check_setup.sh
```

4. Start the next increment:

```bash
./scripts/run_increment.sh
```

5. Monitor the generated artifacts in `prompts/` if you want visibility into each cycle.
6. If you ran with `--no-merge`, finish manually with:

```bash
./scripts/merge_pr.sh
```

### Manual fallback routine

1. Generate the prompt:

```bash
./scripts/gen_prompt.sh
```

2. Review `prompts/next_prompt.md` and send it to Codex manually.
3. After Codex opens the PR, review it:

```bash
./scripts/review_pr.sh
```

4. If approved, merge it:

```bash
./scripts/merge_pr.sh
```

## Notes about the test workflow

The GitHub Actions workflow at `.github/workflows/test.yml` is intentionally scoped to backend validation only.

Current behavior:
- triggers on `pull_request` to `develop` and `main`
- provisions PostgreSQL 15 as a GitHub Actions service
- enables the `uuid-ossp` extension required by the existing migrations
- installs Node.js 18
- runs `npm ci` in `backend/`
- runs `npx knex migrate:latest --env test`
- runs `npm test`

Local validation for the current backend suite remains:

```bash
docker compose --profile test run --rm backend-test
```

## Troubleshooting

- `GEMINI_KEY is not defined`
  - Create the root `.env` or export the variable in your shell.
- `gh CLI was not found in PATH`
  - Install GitHub CLI and ensure it is available in the shell running the script.
- `Docker daemon is not reachable from this shell`
  - Confirm that your user can access Docker and reopen the terminal session after joining the `docker` group, or run `newgrp docker`.
- `Gemini API daily quota exceeded`
  - The orchestrator will schedule an automatic retry if `AUTO_RESUME_ON_RPD=true`. You can inspect `prompts/generated/pending_rpd_resume.json` and `crontab -l` for the scheduled state.
- `Gemini API rate limit hit`
  - The scripts already retry short-lived RPM/TPM limits automatically. If the retries still exhaust, increase `GEMINI_MAX_RETRIES` or reduce prompt size.
- `Prompt source not found`
  - Run `./scripts/gen_prompt.sh` before `./scripts/review_pr.sh` so the increment-specific archived prompt exists.
- `Could not detect an INC-XXX code in the PR title`
  - Rename the PR title so it includes the increment code, for example `INC-001 Close frontend auth session flow`.
- `git user.name is not configured`
  - Configure it locally or globally before using the autonomous flow, for example `git config user.name "your-name"`.
- `run_increment.sh` says the working tree must be clean
  - Commit, stash or discard local changes before starting the autonomous loop.
- `run_increment.sh` keeps waiting for checks
  - Confirm the PR targets `develop` or `main` and that GitHub Actions is enabled for the repository.
