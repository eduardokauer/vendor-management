# AI-assisted Development Pipeline for vendor-management

This repository includes a lightweight framework to reduce the manual loop between planning, implementation, review and merge when working with AI. Instead of rebuilding prompts and review instructions every time, the project keeps a persistent memory of the product state, a clear backlog of increments and a small set of scripts that orchestrate the cycle.

The goal is to make the PM role explicit, keep Codex execution bounded by documented rules and make review repeatable against the original objective and DoD. The developer still decides what to build and when to merge, but the repetitive framing and review work becomes much faster and more consistent.

## Prerequisites

- GitHub CLI (`gh`): https://cli.github.com/
- PowerShell 7+: https://learn.microsoft.com/powershell/scripting/install/installing-powershell
- Gemini API key: https://aistudio.google.com/app/apikey
- VS Code command line (`code`) is optional, but recommended if you want the scripts to open generated files automatically.

## Configure the root `.env`

Create a `.env` file in the repository root if you want the scripts to load environment variables automatically.

Example:

```env
GEMINI_KEY=your_gemini_api_key_here
```

Important:
- This root `.env` is for local orchestration scripts only.
- The application itself still uses `backend/.env`.
- Do not move backend secrets into the root `.env`.

## Framework file structure

The AI-assisted workflow is composed of these files:

```text
docs/project_context.md
docs/pm_workflow.md
docs/codex_workflow.md
prompts/PROMPT_TEMPLATE.md
INCREMENTS.md
scripts/gen_prompt.ps1
scripts/review_pr.ps1
scripts/merge_pr.ps1
.github/workflows/test.yml
scripts/README.md
```

Runtime artifacts generated by the scripts:

```text
prompts/next_prompt.md
prompts/review_result.md
```

## Recommended `.gitignore` additions

This bootstrap does not modify `.gitignore`, but the recommended additions are:

```gitignore
.env

```

## How the pipeline works

1. Update `INCREMENTS.md` with the next desired increment.
2. Run `gen_prompt.ps1` to generate the next Codex prompt from the current project context and the first pending increment.
3. Review the generated prompt and send it to Codex.
4. Let Codex implement the increment, validate the DoD, commit and open a PR against `develop`.
5. Run `review_pr.ps1` to review the PR with Gemini against the original objective, out of scope and DoD.
6. If the review is approved, run `merge_pr.ps1` to squash merge and mark the increment as completed.

## Script usage

### 1. Generate the next Codex prompt

Command:

```bash
pwsh ./scripts/gen_prompt.ps1
```

What it does:
- loads the root `.env` if present
- validates `GEMINI_KEY`
- reads the first pending increment in `INCREMENTS.md`
- reads `docs/project_context.md`, `docs/pm_workflow.md` and `prompts/PROMPT_TEMPLATE.md`
- asks Gemini to act as PM and fill the template
- saves the result to `prompts/next_prompt.md`
- opens the file in VS Code if `code` is available

Expected output:
- a ready-to-paste prompt for Codex in `prompts/next_prompt.md`

### 2. Review the current PR with Gemini

Command for the PR attached to the current branch:

```bash
pwsh ./scripts/review_pr.ps1
```

Command for a specific PR number:

```bash
pwsh ./scripts/review_pr.ps1 -PrNumber 123
```

What it does:
- loads the root `.env`
- validates `GEMINI_KEY` and `gh`
- resolves the PR metadata with `gh pr view`
- downloads the PR diff with `gh pr diff`
- reads `docs/project_context.md`, `docs/pm_workflow.md` and `prompts/next_prompt.md`
- asks Gemini to review the PR against the original objective, out of scope and DoD
- saves the result to `prompts/review_result.md`
- opens the result in VS Code if `code` is available
- returns exit code `0` for approved and `1` for rejected

Expected review output:
- first line must be `STATUS: APROVADO` or `STATUS: REPROVADO`
- item-by-item evaluation of the DoD
- correction prompt for Codex if the PR is rejected

### 3. Squash merge an approved PR and close the increment

Command for the PR attached to the current branch:

```bash
pwsh ./scripts/merge_pr.ps1
```

Command for a specific PR number:

```bash
pwsh ./scripts/merge_pr.ps1 -PrNumber 123
```

What it does:
- validates `gh`
- resolves the PR metadata and asks for confirmation
- runs `gh pr merge --squash --delete-branch`
- switches to `develop` and pulls the latest remote state
- extracts `INC-XXX` from the PR title
- marks the increment as completed in `INCREMENTS.md`
- commits and pushes the increment status update to `develop`

Important:
- The PR title must contain an `INC-XXX` code for automatic backlog completion.
- If the title does not contain an increment code, the script will fail instead of guessing.

## Suggested working routine

1. Keep `develop` updated locally.
2. Create a new branch for each increment.
3. Generate the prompt:

```bash
pwsh ./scripts/gen_prompt.ps1
```

4. Review `prompts/next_prompt.md` and send it to Codex.
5. After Codex opens the PR, review it:

```bash
pwsh ./scripts/review_pr.ps1
```

6. If approved, merge it:

```bash
pwsh ./scripts/merge_pr.ps1
```

7. Generate the next prompt and repeat the cycle.

## Notes about the test workflow

The GitHub Actions workflow at `.github/workflows/test.yml` is intentionally scoped to backend validation only.

Current behavior:
- triggers on `pull_request` to `develop` and `main`
- provisions PostgreSQL 15 as a GitHub Actions service
- installs Node.js 18
- runs `npm ci` in `backend/`
- runs `npx knex migrate:latest --env test`
- runs `npm test`

Local validation for the current backend suite remains:

```bash
docker compose --profile test run --rm backend-test
```

## Troubleshooting

- `GEMINI_KEY is not defined`
  - Create the root `.env` or export the variable in your shell.
- `gh CLI was not found in PATH`
  - Install GitHub CLI and ensure it is available in the shell running the script.
- `prompts/next_prompt.md was not found`
  - Run `pwsh ./scripts/gen_prompt.ps1` before `review_pr.ps1`.
- `Could not detect an INC-XXX code in the PR title`
  - Rename the PR title so it includes the increment code, for example `INC-001 Close frontend auth session flow`.
